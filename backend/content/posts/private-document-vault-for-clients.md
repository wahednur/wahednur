Project files often include contracts, credentials-adjacent documents and source files. They should not sit in a public folder or an old email thread.

## How the vault works

- Files are stored **privately**, not at a public web address.
- A download uses a **short-lived link** created at the moment you click. After a short time it stops working.
- Each file belongs to a project and is shared with the **specific client** it concerns. Another client cannot see it, and does not even learn that it exists.
- Uploads are checked for file type, content and size before they are accepted.
- Removing a file is a soft delete, and actions on files are written to an audit trail.

## What it does not do

It does not make anything magically unbreakable. It removes the common mistakes: public links that never expire, files shared with the wrong person, and nobody knowing who opened what.

## What you should still do

Use a strong, unique password and switch on two-step sign-in on your account. Staff accounts on my side are required to use two-step sign-in.
